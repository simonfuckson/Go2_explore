## 启动

```bash
cd /home/nvidia/go2_explore_ws

# 真实传感器、静止建图、仅预览候选目标；不会使能真实底盘
./run_go2_explore observe room_check_01 --record

# 自动选点和规划连接模拟底盘；实体机器狗不会因此行走
./run_go2_explore explore room_mock_01

# 现场行走入口：就绪后自动申请一次使能并开始探索
./run_go2_explore explore room_real_01 --real
```

每次使用新的地图名。默认打开 RViz 及中文状态面板；无桌面时显式使用 `--no-rviz`。`--no-auto-start` 对应保留的 `auto_start:=false` 调试选项；`--interface eth0` 指定 SDK 网卡，默认保留机器狗原来的 `eth0`。已有地图名及已导出的成果会拒绝覆盖。完整操作及坐标系说明见 `STARTUP_GUIDE_ZH.md`。

在另一个终端使用同一工作空间的命令：

```bash
cd /home/nvidia/go2_explore_ws
./run_go2_explore status
./run_go2_explore rviz  # 当前会话界面关闭后重开，只读
./run_go2_explore save-map
./run_go2_explore stop
# 等探索完全退出后，生成 PGM/YAML 和 2.5D 地形资产
./run_go2_explore export-map room_real_01
```

`stop` 和 Ctrl+C 都先停运动、取消目标、禁用底盘，再保存并退出。保存结果见本次日志目录中的 `session_result.json`。保存失败不算成功。地图输出只在本工作空间的 `maps/<名称>/`。

## 行为

- `observe` 使用真实传感器和原 GO2 地图积累，预览探索候选，底盘为 mock。
- `explore` 默认也使用 mock。只有显式 `--real` 才加载真实 SDK bridge。
- 真机入口先等待建图初始化、有效地图、实时地形和规划器，再申请一次 SDK 使能。成功后至少等待 5 秒，再连续 3 秒确认输入稳定后才准入和发送目标；20 秒无法稳定则禁用，不自动重新使能。
- 保留原持续步行/原地转向门槛，探索上限为 0.30 m/s、0.50 rad/s。禁止倒车及横移，安全门检查整形后的速度。
- 普通障碍会取消目标并等待；旧方向清空，或连续确认停稳且当前轮廓与前方停车范围可通行后，经稳定检查重新选点。暂时性输入故障满足恢复条件后自动重新使能；人工停止、遥控接管、估计器连续性锁止和使能拒绝保持停机。
- 连续 30 秒没有合格前沿或覆盖任务，且期间新增至少两次有效观测、没有活动目标时，停车保存并退出。存在任务但无路径时等待，不报告完成。
- 已观测地面与可通行空间分别保存；覆盖图只增加实际地面观测和真实车体经过区域，碰撞余量不计入已覆盖地面。

## 隔离与恢复原导航

入口只加载系统 ROS 和本工作空间，ROS Master 默认端口 **11321**，地图、日志、ROS 缓存和构建产物独立。启动器沿用原 `run_go2` 的互斥锁，防止两套正式入口同时占用硬件；也检查绕过入口启动的重复驱动和控制进程。不要绕过该启动器直接运行硬件 launch。

原 `/home/nvidia/go2_nav_ws`、原 `run_go2`、用户 `.bashrc` 和系统 SDK 安装均不需要修改。先停止探索，再照常使用原命令即可。探索启动器不会结束原系统的进程。
