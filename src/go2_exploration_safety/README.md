# GO2 探索安全门

速度链固定：`move_base → /cmd_vel_nav → go2_velocity_shaper → /exploration/cmd_vel_shaped → go2_exploration_safety → /cmd_vel_safe → 原 GO2 SDK bridge`。

原始规划指令必须来自 `/move_base`，整形指令必须来自 `/go2_velocity_shaper`。安全门独占最终 SDK 输入。上限为 0.30 m/s、0.50 rad/s，禁止倒车和横移。碰撞检查使用整形后并计入原 SDK 死区/最小转速的有效指令，使用 GO2 轮廓和余量。原始指令单独计时，整形器重复发布不能刷新它。

默认锁定零速。健康准入分别检查里程计初始化、TF、地形、观测图、点云、局部图、当前目标、规划状态和指令新鲜度。使能前健康就绪不依赖底盘已使能；监督器使能后再 arm 并选点。暂时性输入故障可在健康、停稳和范围检查通过后自动恢复，人工停止、控制接管、估计器连续性锁止等不会自动解除。

新增 `auto_reset` 只允许 `fault_recovery.py` 中列明的可恢复原因；必须 SDK 已禁用、无目标、有真实零速度心跳、健康与当前轮廓/前方停车范围通过，并连续 TF 证据确认停稳。该服务只清除指定安全门故障，保持未使能和未 arm。监督器另外要求连续 10 秒健康、至少两次地图更新及真实 SDK 准入，再执行正常使能和姿态稳定流程。原始规划/整形/路径须与新目标重新握手。后续人工停止即使发生在已有地形锁停之后，也永久撤销自动恢复；里程计和传感器健康节点没有新增自动复位入口。

普通障碍触发停车、取消目标和等待，持续清空且输入再次稳定后重新选点。停止命令请使用工作空间入口 `run_go2_explore stop`，它同时管理目标、SDK 禁用、保存和会话退出。诊断见 `/go2_exploration_safety/status`；`reset` 服务自身不使能 SDK，也不自动恢复任务。

探索模式还支持停稳后的替代规划准入：新鲜零速度心跳及多帧 TF 连续确认静止至少 2 秒，然后完整当前轮廓和前方直行停车范围连续安全至少 2 秒，才报告 `OBSTACLE_REPLAN_READY`。它不发布候选速度，仍保持暂停和零输出；监督器完成稳定等待与新目标握手后才可运动。未知格、原始竖直障碍和完整车体余量继续参与检查，硬故障永不由此解除。诊断包含 `standstill_confirmed`、`replan_candidate_clear` 和 `obstacle_replan_ready`。

纯算法与门控周期测试位于 `test/`。本次仅验证模拟控制，实体停车效果必须现场验收。
